---
title: URL state parsers
description: Shared nuqs parsers for URL state — server and client entries.
---

The app-wide URL state schema (see [useSearchParams](/docs/hooks/use-search-params)) lives here in two entry points:

## `rockin/utils`

Server entry. Exports `searchParams` (nuqs parser definitions), `searchParamKeys` (the short URL keys: `q`, `c`, `status`, `u`, `id`, `tp`, …) and `SearchParams` — a `createLoader` for reading the state in server components:

```tsx
import { SearchParams } from "rockin/utils"

type Search = { searchParams: Promise<Record<string, string | string[] | undefined>> }

export default async function Page({ searchParams }: Search) {
  const { query, category, page } = await SearchParams(searchParams)
  return <p>Query: {query} · Page: {page}</p>
}
```

Parsers include a positive-int page parser (default `1`), literal `productStatus` values (`active` / `draft` / `archived`) and boolean flag parsers for `cart` / `notification` (default `false`).

## `rockin/utils/parms-client`

Client entry for reading and serializing flags without the nuqs loader:

```tsx
import { hasFlagSearchParam, buildFlagSearchParamHref } from "rockin/utils/parms-client"

// "?cart" — bare flags, perfect for open/close animations
const isOpen = hasFlagSearchParam(params, "cart")
const href = buildFlagSearchParamHref(pathname, params, "notification", true)
```
